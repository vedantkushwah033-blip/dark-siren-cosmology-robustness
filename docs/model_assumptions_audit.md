# Model assumptions audit: dark-siren sensitivity study

## Purpose and scope

This note records what the pinned synthetic simulator actually implements, so that the paper does not overstate what the experiment demonstrates. The audit is based on the source files in the pinned original project, especially `src/experiments.py`, `src/simulations_v2.py`, `src/completeness.py`, and `src/bayesian_inference.py`.

This is a controlled toy-model sensitivity study. It is not a reanalysis of LVK events, a measurement of the real Hubble constant, or a survey-calibrated forecast.

## Data-generating model observed in source

- Each mock universe contains 500 galaxies by default. Redshifts are sampled between 0.005 and 0.08 with a distribution proportional to the low-redshift comoving-volume approximation, implemented by sampling uniformly in $z^3$.
- Galaxy distances are generated from the simplified low-redshift relation used by the project's cosmology helper. The source path should not be described as a full relativistic luminosity-distance calculation unless the cosmology implementation is upgraded and validated.
- A luminosity proxy is drawn log-uniformly from $10^9$ to $10^{11.5}$. A mass proxy is constructed from luminosity plus log-normal scatter. These are synthetic proxies, not measured galaxy properties and not a calibrated luminosity function or stellar-mass function.
- One host is selected from the full parent population using either uniform, luminosity-proxy, or mass-proxy weights.
- One mock GW distance is generated with Gaussian noise. The default uncertainty is 15% of the true host distance, so the legacy data-generating uncertainty changes with the true distance and therefore with the host. This dependence is a known limitation and is why calibration diagnostics must state the noise design explicitly.
- Catalogue masks retain an exact rounded number of galaxies. Random missingness samples a fixed-size subset uniformly. The redshift-dependent mask samples a fixed-size subset with probabilities proportional to $1/(z+10^{-9})$. This is a controlled selection mechanism, not a fitted survey selection function.
- The inference likelihood is a weighted mixture of Gaussian distance likelihoods at candidate redshifts, with the low-redshift relation $d ≈ cz/H_0$. The default inference grid is $H_0 ∈ [50,90]$ km s$^{-1}$ Mpc$^{-1}$. This is a simplified one-event model, not a complete dark-siren hierarchical analysis.

## Interpretation boundaries

1. **Catalogue incompleteness:** the selection experiments test the specified fixed-size masks. They do not establish the impact of real catalogue incompleteness without a survey-informed selection model and realistic galaxy population.
2. **Host-weight mismatch:** luminosity and mass are proxies generated by the simulator. A mismatch between generating and inference weights is a deliberate stress test, not evidence that a particular real host prior is correct or incorrect.
3. **Hidden-host/oracle term:** when enabled, the missing-host component uses the known hidden population from the simulation. This is an oracle validation control unavailable in a real analysis unless external information supplies the missing population. It must be labelled as such.
4. **Coverage:** empirical interval coverage is a repeated-sampling property under the exact simulated data-generating process. A nominal 68% Bayesian credible interval is not guaranteed to have 68% frequentist coverage at every fixed true $H_0$, especially under prior sensitivity or model mismatch.
5. **Calibration:** simulation-based calibration validates computation only for the model used to generate the synthetic data and the matched inference model. It does not validate the realism of the data-generating assumptions.
6. **Pairing:** same seeds and run indices are not, by themselves, proof of valid pairing. The simulator reuses the same parent catalogue and host/GW random seeds when the relevant scenario parameters are held fixed; masks are scenario-specific transformations. Paired contrasts must only compare scenarios for which the intended common random quantities are genuinely shared.

## Required reporting for the main factorial experiment

Report, per scenario, the number of valid replicates, median and mean posterior error, RMSE, empirical 68% and 95% coverage with Monte Carlo standard errors, mean credible-interval widths, host-observed fraction, and realized catalogue completeness. Report effect sizes with uncertainty for prespecified contrasts. Keep all per-run records and the pinned source commit with the results.

Do not report a single metric in isolation: a scenario can improve coverage by producing wider intervals, and interval width must be interpreted alongside bias and RMSE.

## Upgrade path before observational claims

Before making claims about real dark-siren inference, replace or validate the simplified distance-redshift relation, model the GW detection/selection process, introduce a survey-informed galaxy selection/completeness model, justify the host-population prior with astrophysical evidence, and test the method on appropriate public GW and galaxy-catalogue data. These are future extensions, not accomplishments of the present synthetic study.
