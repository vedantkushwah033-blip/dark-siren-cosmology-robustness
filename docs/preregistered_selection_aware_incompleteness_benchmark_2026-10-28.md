# Preregistered design sketch: selection-aware catalogue incompleteness benchmark

**Status:** proposed protocol only; not implemented or validated.  
**Created:** 2026-10-28  
**Purpose:** define a falsifiable next-stage synthetic experiment before committing to a GP implementation or running a large simulation.

## 1. Research question

When a galaxy catalogue is incomplete and its missing galaxies retain redshift clustering, how do (i) homogeneous missing-host completion and (ii) a flexible reconstruction of the latent galaxy redshift distribution differ in their downstream H0 inference, once catalogue selection and GW detection selection are treated consistently?

The question is not whether a GP always wins. A flexible reconstruction may be less stable when the catalogue is very sparse, the kernel is misspecified, or hyperparameter uncertainty is ignored.

## 2. Scope boundary

This benchmark is distinct from existing finite-host robustness experiments and from the unavailable-input CHIMERA v2.2 reproduction. It must use synthetic truth generated by this repository and must not be described as a reproduction of Tagliazucchi et al. (2026). No real GW events, real-data H0 estimate, or external validation claim is in scope.

## 3. Generative model (minimum viable version)

1. Choose a bounded redshift domain, for example z in [0.01, 0.4], and define a known latent galaxy intensity with at least two overdensity/underdensity features. Keep the intensity positive by construction and record its normalization.
2. Generate a parent galaxy population from that intensity. Apply a declared catalogue detection probability S_cat(z, m) or, in the initial toy, S_cat(z) with a smooth redshift dependence. Retain the full parent catalogue only as simulation truth; inference arms may see only the detected catalogue and the declared selection function.
3. Generate GW host redshifts from the latent galaxy population multiplied by a declared merger-rate weight. Keep the host-draw mechanism fixed across paired arms.
4. Generate luminosity-distance measurements under a declared cosmology and noise model. For the first unit-tested prototype, a low-redshift approximation may be used, but it must be labelled as such; an exact luminosity-distance relation should be a separate, tested extension.
5. Apply a GW detection rule with an explicit probability P_det(d, other declared variables). Either condition the likelihood on detection and include the corresponding detection-efficiency normalization, or use a generative likelihood that models event counts. The selected convention must be written mathematically before simulations are run.

All random seeds, parameters, units, truncations, and distributions must be committed in a machine-readable configuration before the full experiment.

## 4. Inference arms

- **Complete-catalog oracle:** uses the latent complete galaxy population. This is a lower-bound / diagnostic reference, not a deployable estimator.
- **Homogeneous completion:** uses the observed catalogue plus a predeclared missing-galaxy redshift component based on the chosen homogeneous baseline (e.g. uniform in comoving volume), with completeness treated as specified by the design.
- **Flexible reconstruction:** reconstructs the latent redshift intensity from the incomplete catalogue using a GP or another explicitly named positive density model, with catalogue selection in the catalogue likelihood. Uncertainty in the reconstructed intensity should be propagated or the plug-in approximation explicitly declared.
- **Optional misspecification control:** a flexible model with a deliberately wrong kernel/selection assumption to measure sensitivity rather than cherry-pick a favorable model.

Do not feed the true latent intensity, true missing fraction, or fitted-to-truth GP hyperparameters to a non-oracle arm. If completeness is assumed known, include a sensitivity arm where it is estimated or perturbed.

## 5. Primary estimands and metrics

Choose one primary downstream estimand before the full run. Suggested primary metric: paired difference in absolute H0 estimation error between flexible reconstruction and homogeneous completion, averaged over the prespecified catalogue-completeness and clustering conditions.

Secondary metrics:
- signed bias and RMSE of posterior median H0;
- empirical coverage of central 68% and 95% credible intervals;
- average interval width;
- calibration diagnostics (PIT or rank statistics, where their assumptions apply);
- latent-intensity reconstruction error on a fixed redshift grid;
- failure/convergence rate and compute cost.

Report oracle comparisons separately. Never describe oracle performance as achievable by the non-oracle methods.

## 6. Experimental factors and pairing

Start with a small, prespecified factorial:
- catalogue completeness: moderate and severe;
- clustering amplitude: weak and strong;
- GW distance uncertainty: lower and higher;
- catalogue selection correctly specified versus deliberately misspecified in a separate robustness arm.

Use identical underlying latent populations and paired GW realizations across methods within each replicate. Use independent replicates for uncertainty intervals over the performance contrast. Report cell-level outcomes before any marginal average, and specify whether summaries weight cells equally or weight by replicate count.

Choose replicate counts using a pilot precision calculation for the primary contrast, not by stopping when results look favorable. Record all attempted runs and failures.

## 7. Required correctness gates before scaling up

1. **Catalogue likelihood tests:** recover the known detected-catalogue distribution under the correctly specified selection model in a tractable toy case.
2. **Selection normalization tests:** independently calculate detection efficiency and confirm that the event likelihood and its selection correction use the same population assumptions.
3. **Oracle sanity check:** with a complete catalogue and correctly specified GW model, verify that H0 inference behaves as expected over interior truths.
4. **Simulation-based calibration:** check posterior rank behavior under repeated prior-predictive simulations; investigate deviations rather than treating a single uniformity score as proof of correctness.
5. **Coverage:** report truth-specific coverage, separate boundary truths from interior truths, and compare credible intervals with an appropriate reference procedure where possible.
6. **Grid/numerical stability:** repeat selected cases on finer grids and independently reconstruct posterior summaries.
7. **Reproducibility:** save raw replicate-level results, configuration, software versions, seeds, checksums, and an audit script that recomputes summary tables from raw records.

If any gate fails, stop before the expensive factorial and diagnose the failure. Do not patch a metric threshold merely to pass.

## 8. Decision rules and interpretation

The flexible method is not deemed superior from narrower intervals alone. A precision gain is only favorable if bias and calibration remain acceptable under the prespecified conditions. If the GP narrows intervals but worsens bias or coverage, report that trade-off as a central finding. If no robust advantage appears, report the null or conditional result rather than expanding the design post hoc.

## 9. Relationship to current code and external references

The current `dataset_likelihood.py` prototype combines independent event likelihoods under a shared uniform H0 prior; its module docstring explicitly excludes selection conditioning, event-rate inference, and shared nuisance parameters. It is not ready to run this benchmark as specified.

The 2026 GP catalogue-incompleteness paper is a motivation and comparison reference, not a source of data for this project:
- Tagliazucchi et al., *Phys. Rev. D* 114, 083523 (2026), DOI [10.1103/vmzf-1wxq](https://doi.org/10.1103/vmzf-1wxq).
- Publisher abstract: https://journals.aps.org/prd/abstract/10.1103/vmzf-1wxq.

The exact CHIMERA v2.2 notebook input bundle remains a separate provenance gate. Do not silently substitute v2.0 inputs or imply the synthetic benchmark reproduces CHIMERA.

## 10. Go/no-go

**Current decision: NO-GO for a full GP-versus-homogeneous performance run.** Proceed first with a mathematically specified toy generative model, selection-likelihood contract, and small correctness tests. Only promote this sketch to an implementation plan after reviewing the model equations and testable assumptions.
