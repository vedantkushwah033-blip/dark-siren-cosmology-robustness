## 1. Executive decision

**NO-GO for the proposed R=400 confirmatory campaign and for integrating bootstrap-propagation claims into the manuscript.** The current repository supports a nonlinear estimated-inclusion pilot and exploratory resampling of posterior means, but it does not yet establish calibrated uncertainty propagation for the nonlinear posterior functional.

However, several objections in the supplied hostile review are overstated or do not describe the current implementation:

1. The current estimated-inclusion path does **not** combine an IPW-corrected catalogue term with an explicit missing-host mixture. The claimed IPW-plus-mixture double counting is therefore not demonstrated in the inspected code.
2. The current toy likelihood uses an unconditional pre-detection event-distance density and divides by the matching detection efficiency once. The fact that the observed data were generated by rejection sampling above the detection threshold does not itself mean the numerator is already selection-conditioned.
3. The (1/3) quadratic centering constant is correctly documented as a uniform-reference centering convention. Nonuniform parent covariates affect coefficient interpretation and correlation, but do not make the nonlinear stress experiment meaningless.
4. The supplied `BootstrapInclusionPropagator` is not the current repository implementation. The actual module is `posterior_validation_bootstrap.py`, whose docstring explicitly disclaims bootstrap validity and whose output intervals describe resampling variability of posterior means, not credible intervals for (H_0).

The strongest valid objections are the need to define the inferential target for validation uncertainty, distinguish shared-frame and independent-cohort designs, verify the complete generative likelihood, expand and preregister the factorial design, and avoid presenting bootstrap resampling distributions as Bayesian uncertainty.

## 2. Critical likelihood audit

### 2.1 What the inspected implementation actually computes

In `src/dark_siren_robustness/selection_toy.py`, the declared model is

[
dmid z,H_0sim N(cz/H_0,sigma^2),qquad
mathrm{detected}iff dge d_{m threshold}.
]

For a normalized pre-detection host-redshift density (q(z)), the code computes

[
p(dmid H_0,q)=int q(z),
  phi(d;cz/H_0,sigma),dz,
]

and

[
eta(H_0,q)=int q(z),
  P(dge d_{m threshold}mid z,H_0),dz.
]

It then returns

[
log L_{m cond}(H_0)
=sum_{k=1}^{N_{m det}}log p(d_kmid H_0,q)
-N_{m det}logeta(H_0,q).
]

This is the density of detected distances conditional on the fixed observed count, provided the supplied (d_k) are drawn from the same pre-selection model and threshold rule. The generator in `src/dark_siren_robustness/generative_selection.py` repeatedly draws hosts from the parent host distribution, draws Gaussian distances, and retains only distances above the same threshold until the requested number of detections is obtained. That rejection sampler generates observations from the truncated distribution; it does not mean the likelihood numerator in `selection_toy.py` has already been truncated. The denominator is therefore not automatically a double-counting error.

### 2.2 Important limitation

The implementation is a low-redshift Euclidean toy model with a hard threshold on measured distance. It is not a realistic gravitational-wave detector selection model. This limitation is already stated in the source docstrings and must remain prominent in the manuscript.

### 2.3 Required follow-up tests

Before treating this likelihood as validated, add or independently run tests that:
- compare numerical (eta(H_0)) with an independent high-accuracy quadrature calculation;
- verify that simulated detected distances follow the normalized truncated density for fixed (H_0);
- check that the empirical detection fraction agrees with (eta(H_0)) in a large independent simulation;
- verify that the conditional density integrates to one over the detected-distance domain;
- confirm the fixed-count interpretation and explicitly state that no event-rate information is used.

The supplied review's generic warning about numerator/denominator consistency is correct as a principle. Its claim that the current code necessarily double-counts selection is not supported by the inspected source.

## 3. Catalogue inclusion weighting and the alleged IPW-plus-mixture problem

The current estimated-inclusion implementation follows this path:

- `estimated_inclusion.py`: fit a logistic model to validation redshifts and catalogue-retention indicators; predict (hatpi(z_j)) for retained catalogue objects.
- `catalogue_density.py`: form inverse-inclusion weights (1/hatpi(z_j)), estimate a weighted KDE, multiply by the declared merger-rate weight, and normalize the resulting host density.
- `selection_toy.py`: use that one normalized host density in both the event-distance numerator and the detector-selection normalization.

There is no explicit missing-host mixture parameter (f), no separate (L_{\rm miss}) term, and no mixture normalization ((1-f)\alpha_{\rm cat}+f\alpha_{\rm miss}) in this inspected path. Thus the review's proposed M1/M2/M3 choice does not map directly onto the current estimated-inclusion code.

This does not prove every historical likelihood implementation is correct. It means the alleged double-counting must be demonstrated against a specific source path and generative model before changing anything. Do not remove or add a missing-host term based only on the supplied schematic equation.

## 4. Quadratic centering: correct the interpretation, not the experiment

The source uses

[
eta(x)=a+bx+gamma(x^2-1/3).
]

The code comment explicitly says (1/3) is the second moment under a uniform reference measure on ([-1,1]), not under the nonuniform parent-redshift distribution. The hostile review is correct that this does not generally make the quadratic feature orthogonal to the linear feature under the simulated parent distribution.

But the stronger conclusion—that the misspecification arm becomes scientifically meaningless—is incorrect. A nonzero quadratic term still makes the true logit nonlinear, and a degree-one logistic fit remains a deliberately restricted model. The constant subtraction changes the intercept parameterization; it does not remove the curvature.

Required reporting:
- give the empirical parent-frame moments (E[x]), (E[x^2]), (E[x^3]) and the covariance/correlation of (x) with (x^2-1/3);
- report the actual inclusion-probability range and low-probability fractions for every (gamma);
- describe (gamma) as a curvature parameter under a fixed reference-basis convention, not as an orthogonal component under the actual parent law.

Do not replace (1/3) with an empirical moment after seeing outcomes. That would change the declared DGP and requires a dated protocol revision and fresh confirmatory seeds. If a distribution-orthogonal basis is desired, define it prospectively and treat it as a separate experiment.

## 5. Validation design and leakage

The pilot source explicitly distinguishes:
- a shared finite parent frame, where the audit records are sampled from the same parent frame that generated the retained catalogue; and
- an independent audit cohort, generated separately under the declared latent intensity and retention law.

The hostile review is right that shared-frame validation is not external validation. It is also not inherently invalid: it is a specified finite-frame sampling design, and its dependence with the retained catalogue is part of the design. The independent cohort addresses a different transport/generalization question. The two designs must be reported separately.

The source constructs shared-frame audit records from a random permutation of parent-frame indices and uses nested prefixes for validation sizes. The paired estimator comparisons share the parent/catalogue/GW realization. This is a defensible paired design if the auditor verifies the index lineage and the only intended arm difference. It is not proof of independence between validation and catalogue data.

Required audit:
- reconstruct the validation indices from the saved seed;
- verify SRSWOR and nested-prefix properties;
- verify the same records are supplied to linear and quadratic fits at each size;
- verify independent-cohort inputs are separately generated and never silently pooled with shared-frame results;
- state that shared-frame performance is internal finite-frame calibration, not external validation.

## 6. Bootstrap and uncertainty propagation: the central unresolved issue

The proposed `BootstrapInclusionPropagator` in the user-supplied report is not the code currently present in the repository. The inspected module is `src/dark_siren_robustness/posterior_validation_bootstrap.py`.

That module:
- refits the inclusion model on resampled validation records;
- rebuilds the weighted host density;
- recomputes the selection-conditioned posterior;
- preserves failed attempts;
- stores posterior-density draws and posterior-mean draws;
- labels the pseudo-population/SRSWOR construction exploratory;
- explicitly says its intervals summarize resampling variability of posterior means, not (H_0) posterior credible intervals;
- labels the scalar FPC adjustment diagnostic only.

This is appropriately cautious. It is not yet a validated uncertainty-propagation procedure.

### 6.1 Why averaging log-likelihood curves is not automatically Bayesian marginalization

For validation data (V), a Bayesian marginal likelihood contribution would be

[
p(dmid H_0,V)=
int p(dmid H_0,eta),p(etamid V),deta,
]

and the resulting posterior is proportional to

[
p(H_0)int p(dmid H_0,eta)p(etamid V),deta.
]

With draws (eta^{(b)}) from the actual posterior (p(etamid V)), the integral can be approximated on the likelihood scale using a log-sum-exp calculation:

[
log p(dmid H_0,V)approx
operatorname{logsumexp}_b{log p(dmid H_0,eta^{(b)})}-log B.
]

Averaging log-likelihoods instead gives the log of a geometric mean of likelihoods, not the log of their arithmetic marginal average. Averaging normalized (H_0) posteriors is also not generally equivalent unless the weights and conditioning are defined correctly. Crucially, ordinary bootstrap coefficient draws are not automatically draws from (p(etamid V)).

Therefore:
- do not call a bootstrap ensemble a Bayesian posterior over inclusion coefficients;
- do not use Rubin's multiple-imputation rules for posterior quantiles without a derivation tailored to the target;
- do not call the bootstrap percentile interval a credible interval for (H_0);
- use repeated-sampling calibration to evaluate the actual procedure if the goal is frequentist coverage.

### 6.2 Finite-population resampling

The hostile review is right that the sampling design matters, but it overstates the rule that every with-replacement bootstrap is invalid under SRSWOR. Validity depends on the estimand, sampling fraction, design, and chosen finite-population bootstrap. The repository's pseudo-population construction is explicitly exploratory and should not be described as a proven design-valid bootstrap.

The next defensible step is not to declare one bootstrap “correct.” It is to compare candidate uncertainty procedures against repeated SRSWOR samples from known finite parent frames, using the actual finite-frame posterior functional as a reference. Report bias, empirical SD, mean estimated SE, interval coverage, interval width, and failure rates.

## 7. Factorial design and estimands

The current protocol already proposes curvature levels and validation sizes, and the pilot runner accepts validation sizes. Therefore the hostile review's statement that the repository design has no validation-size factor is not accurate for the current protocol.

However, the user's proposed (R=400), (gammain{0,pm1,pm2}), and (N_{\rm val}in{100,300,1000}) are not the same as the current protocol's candidate curvature levels ({-1.2,-0.6,0,0.6,1.2}). Do not combine or silently substitute these. The confirmatory design is not frozen. The current pilot's default replicate count is explicitly non-confirmatory.

The proposed (N_{\rm events}=300) also differs from the current pilot default (N_{\rm detected}=30). Increasing event count changes posterior precision and potentially the relative contribution of host-density uncertainty. It is a scientific design change, not a harmless runtime setting.

Before confirmatory work, freeze:
- curvature values and parameterization;
- parent-frame size and generation law;
- detected-event count and distance model;
- validation sample sizes and nesting;
- shared-frame versus independent-cohort estimands;
- primary endpoint and contrast;
- interval/coverage definitions;
- failure treatment;
- Monte Carlo precision targets and multiplicity strategy.

The existing protocol's primary contrasts are absolute posterior-mean error reductions. Coverage, width, density ISE, and inclusion-probability MAE are separate secondary outcomes. A falsification rule based on “improvement >5%” must define the sign, scale, reference arm, and uncertainty interval. If claiming practical equivalence, predefine margins and use an equivalence procedure; failure to reject a difference is not evidence of equivalence.

## 8. Prioritized corrections

### P0 — before any confirmatory simulation
1. Freeze the exact target estimand for validation uncertainty: finite-frame estimator variability, fixed-truth frequentist coverage, or Bayesian marginal posterior. Do not conflate them.
2. Verify the generative likelihood with the independent normalization tests in Section 2.3.
3. Preserve the existing separation between catalogue inclusion and GW detection. Do not introduce a missing-host mixture without deriving it from the same generative model.
4. Freeze one coherent factorial design; reconcile the competing (gamma), validation-size, and event-count settings.
5. Verify shared-frame and independent-cohort sample lineage and all paired seed relationships.
6. Retain all failures and report unconditional success/failure alongside complete-case paired contrasts.

### P1 — before manuscript claims about estimated inclusion
7. Independently regenerate pilot artifacts from primitive seeds and audit all inputs, outputs, and checksums.
8. Report parent-distribution moments and inclusion-probability support for every curvature condition.
9. Evaluate pre-posterior diagnostics against held-out repeated-sampling outcomes; until then call them candidate diagnostics, not predictors.
10. Report MC uncertainty for bias, RMSE, coverage, paired differences, and failure rates.

### P2 — manuscript and publication quality
11. Clearly distinguish catalogue inclusion from detector selection and fixed-count conditioning from rate inference.
12. Keep oracle results labelled diagnostic-only.
13. Soften novelty claims to a synthetic application of established selection-model and survey-sampling ideas unless a systematic literature review supports stronger claims.
14. Retain all limitations: simplified Euclidean distance model, hard distance threshold, synthetic population, no real detector response, no real survey validation, and no (H_0) measurement.
