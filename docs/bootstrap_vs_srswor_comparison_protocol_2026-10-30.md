# Prespecified bootstrap-versus-SRSWOR comparison protocol

**Status:** design specification only; no bootstrap-versus-SRSWOR numerical result is claimed.

## 1. Objective

Determine whether the ordinary paired-record nonparametric bootstrap estimates the repeated-sampling uncertainty of the validation-based host-weighting estimator when the actual validation design is simple random sampling without replacement (SRSWOR) from a finite parent frame. Evaluate whether a first-order finite-population correction (FPC) improves calibration, and whether any variance-calibration difference materially propagates to the toy H0 posterior mean.

The study is conditional on a fixed parent frame, catalogue-retention indicators, incomplete observed catalogue, and GW distance observations within each scenario. It is not a real GW analysis.

## 2. Target estimands and reference distribution

For scenario s, let the finite parent frame contain N fixed paired records (z_i, R_i), where R_i is the catalogue-retention indicator. Let T_s(S_n) be the posterior mean of H0 obtained by fitting the declared logistic inclusion model on validation subset S_n, applying inverse-probability weighting to the fixed observed catalogue, estimating the reflected weighted KDE, and evaluating the fixed selection-aware toy likelihood.

Define the finite-frame reference T_s,N as the same complete estimator applied to all N paired validation records. This is a finite-frame plug-in target, not an oracle truth for a superpopulation and not the true H0.

The design-based reference distribution is generated by repeated independent SRSWOR samples of size n from the fixed N-record frame. Its reference standard deviation is the empirical standard deviation of T_s(S_n) around the scenario-specific finite-frame target, with Monte Carlo uncertainty reported.

Separately report bias and RMSE relative to the known simulation H0. Do not conflate finite-frame estimation error with physical H0 error.

## 3. Paired bootstrap estimators

For every outer SRSWOR sample S_n:

1. Resample n paired records (z_i, R_i) with replacement.
2. Refit the same bounded logistic model from scratch.
3. Recompute inverse-inclusion weights, reflected KDE, selection-aware likelihood, and posterior mean.
4. Record invalid one-class samples, optimizer failures, boundary-limited fits, and any invalid weights as failures. Do not silently discard or replace them.

From B valid bootstrap replicates, compute:
- ordinary bootstrap SE: sample SD of bootstrap posterior-mean estimates;
- ordinary percentile interval: 2.5th and 97.5th percentiles;
- FPC-adjusted SE: ordinary bootstrap SE multiplied by sqrt(max(0, 1 - n/N));
- FPC-adjusted normal interval: outer estimate ± 1.96 × FPC-adjusted SE.

The FPC adjustment is a candidate first-order correction, not an assumed solution. It may be inaccurate for nonlinear estimators, model fitting near boundaries, or unstable inverse weights. Compare it empirically.

The bootstrap resamples paired records. Never resample redshifts and retention labels independently.

## 4. Primary comparisons

Within each scenario and validation size, estimate the SRSWOR reference SD across outer validation samples. Compare it with:
- mean ordinary bootstrap SE;
- mean FPC-adjusted bootstrap SE;
- median and interquartile range of both bootstrap SE distributions.

Primary variance-calibration ratios:
- ordinary ratio = mean(ordinary bootstrap SE) / empirical SRSWOR SD;
- FPC ratio = mean(FPC-adjusted bootstrap SE) / empirical SRSWOR SD.

Also report squared-error calibration, interval coverage of the finite-frame target T_s,N, mean interval width, failure rate, boundary-limited fraction, effective sample size, maximum and 99th-percentile inverse weights, and the fraction of outer samples with bootstrap failure rate above a preregistered threshold.

For posterior-mean intervals, evaluate both 95% coverage of T_s,N and error relative to known H0 as separate outcomes. The H0 posterior's own 68% credible interval is a different object and must not be called a bootstrap confidence interval.

## 5. Experimental hierarchy

- Top-level independent unit: parent scenario.
- Nested within scenario: repeated SRSWOR outer validation samples.
- Nested within each outer sample: bootstrap replicates.

Validation sizes should use the existing nested-prefix design so comparisons across n are paired. Do not treat outer draws or bootstrap replicates as independent parent scenarios.

## 6. Staged computation

### Deterministic unit tests
- Exact SRSWOR sample indices are unique and within the parent frame.
- Bootstrap indices are sampled with replacement and retain paired record alignment.
- Replaying seeds exactly reproduces indices and outputs.
- FPC factor equals sqrt(1 - n/N), with explicit handling when n=N.
- All-failure and one-class bootstrap samples are counted and surfaced.
- A synthetic linear finite-population mean test verifies that ordinary bootstrap variance is expected to exceed SRSWOR variance by approximately the FPC relationship under suitable conditions. This is a code sanity check, not evidence for the nonlinear estimator.

### Smoke
One scenario, two validation sizes, a few outer draws, and a small B. Verify schemas, accounting, deterministic replay, and independent numerical reconstruction only.

### Pilot
Start with 20 independent parent scenarios, 30 outer validation draws per size, and B=100 bootstrap replicates per outer sample. Estimate runtime, failure rate, scenario-level variance, bootstrap Monte Carlo noise, and the distribution of calibration ratios. These are implementation/pilot outputs only.

### Confirmatory design
Choose scenario and outer-draw counts by simulation-based precision analysis after the pilot. A reasonable initial target is a 95% interval half-width no larger than 0.10 for the mean SE-calibration ratio and no larger than 0.02 for key interval-coverage estimates, but revise these targets if computational feasibility or nested variance indicates otherwise. Use enough bootstrap replicates that Monte Carlo error in each reported bootstrap SE is negligible relative to outer-sampling variability; demonstrate this with B-doubling diagnostics.

Freeze seeds, model specification, bandwidth, H0/redshift grids, sample sizes, bootstrap method, FPC rule, exclusions/failure handling, primary endpoints, and analysis code before the confirmatory run.

## 7. Independent audit requirements

The artifact must preserve:
- exact parent-frame and validation-record hashes;
- scenario, outer-draw, sample-size, and bootstrap seeds;
- SRSWOR indices and bootstrap indices;
- finite-frame target fit and posterior summary;
- every bootstrap success/failure mask and failure reason;
- bootstrap coefficient, weight, density, and posterior diagnostics;
- raw outer-sample estimator values;
- derived scenario-level and overall summaries.

The independent auditor must regenerate parent inputs and thinning, replay both sampling layers, independently refit the logistic model, reconstruct the weighted KDE and posterior for all successful outer and bootstrap fits, and rederive all aggregate metrics. Add tamper tests for indices, seeds, coefficient values, densities, posterior summaries, and aggregate summaries.

## 8. Interpretation safeguards

- Ordinary bootstrap over paired records is not automatically design-consistent for SRSWOR from a finite frame.
- The FPC is not guaranteed to repair nonlinear estimator uncertainty.
- Boundary-limited logistic fits, weak positivity, and extreme weights can invalidate simple normal approximations.
- If ordinary bootstrap is calibrated in some regimes and not others, report the regime map rather than a single global verdict.
- If the benchmark shows negligible practical difference, report that result. Do not manufacture a failure narrative.
- Results are conditional on the declared synthetic parent distribution, catalogue selection, merger weighting, fixed GW sample, Gaussian distance toy, and finite grids.

## 9. Decision gate

Do not start the confirmatory run until:
1. the finite-parent estimator auditor passes on all smoke artifacts;
2. the bootstrap implementation passes deterministic and adversarial tests;
3. the pilot estimates computational cost and failure behavior;
4. a precision plan is frozen;
5. the exact-head CI matrix is green on all supported Python versions.

This protocol is a research design, not a result or a claim of novelty.


## 10. Literature-informed design-bootstrap comparator (required before confirmatory work)

A literature check on 30 October 2026 identified established survey-sampling bootstrap methods specifically designed for finite-population sampling. In particular, the 2022 JRSSB paper *Bootstrap Inference for the Finite Population Mean under Complex Sampling Designs* treats SRSWOR among several designs and describes generating bootstrap finite populations, applying the original sampling design to those populations, and studentizing. This means the current ordinary paired-record bootstrap plus scalar FPC comparison is not a sufficient survey-methods benchmark by itself.

Before confirmatory runs, add a design-aware resampling comparator suitable for the stated SRSWOR validation design. Candidate family: a pseudo-population/design-bootstrap approach that represents finite-population uncertainty and reapplies SRSWOR within each bootstrap population. The exact algorithm, finite-population construction, studentization, and any calibration must be selected from the published method and its assumptions—not improvised from the scalar FPC—and implemented as a separately named arm. The implementation must be checked against the source method's conditions and a simple finite-population mean benchmark where the expected design variance is known.

Required arms for the revised comparison:
1. Ordinary paired-record with-replacement bootstrap (naive baseline).
2. Ordinary bootstrap SE multiplied by the first-order FPC (simple correction baseline).
3. A literature-grounded design-aware finite-population bootstrap appropriate to SRSWOR (primary methodological comparator, subject to its assumptions).
4. Empirical repeated-SRSWOR distribution (simulation reference).

Do not label arm 3 as valid for the nonlinear logistic/KDE/posterior estimator merely because it is valid in a related survey setting. Its behaviour must be measured. If the published method's assumptions do not transfer to the estimator or validation design, document the mismatch and treat the method as an exploratory comparator rather than a valid default.

This addition changes the experiment's scope and compute budget. The pilot must compare all three resampling arms, quantify each arm's Monte Carlo error, and estimate runtime before freezing confirmatory sample sizes. Update the protocol, auditor schema, and paper's related-work section before running confirmatory experiments. The candidate contribution remains a comparative calibration study, not invention of a new bootstrap method.


## 11. Implemented exploratory pseudo-population resampling primitive (30 October 2026)

The repository now contains `design_aware_srswor_bootstrap_indices` in
`src/dark_siren_robustness/design_aware_srswor_bootstrap.py`. It follows the
SRSWOR construction in Wang, Peng & Kim (2022):

1. Given n observed paired validation records, draw multinomial replication
   counts `Multinomial(N; 1/n, ..., 1/n)`.
2. Expand those counts into a size-N pseudo-population of indices into the
   original paired records.
3. Draw n positions without replacement from the pseudo-population.
4. Map those positions back to the original paired-record indices.

The function returns pseudo-population indices, mapped bootstrap-sample
indices, and the selected positions within the pseudo-population. Persisting
all three makes the multinomial construction and the without-replacement draw
exactly replayable; redshift and catalogue-retention indicators always use the
same mapped record indices.

The new
`bootstrap_validation_inclusion_density_design_aware` function in
`estimated_inclusion.py` applies this construction to the validation-based
logistic inclusion model and weighted host-density estimator. For each
replicate it stores:
- the complete pseudo-population index vector;
- the SRSWOR sample indices mapped to the original paired records;
- the full pseudo-population fitted density and logistic coefficients, which
  provide a finite-pseudo-population plug-in reference;
- the bootstrap-sample fitted density and diagnostics;
- the success mask and failure reasons.

**Scope limitation:** this is an exploratory implementation of the
pseudo-population resampling construction at the host-density-estimation
layer. The published second-order accuracy result in Wang, Peng & Kim (2022)
is for finite-population mean inference under stated regularity conditions.
It does not establish validity for our nonlinear bounded-logistic,
inverse-weighted KDE, or downstream Bayesian posterior mean. No posterior
bootstrap interval or calibration result is produced by this function yet.
The full posterior-level comparator, studentization/interval construction,
independent auditor, and finite-population-mean benchmark remain required.


## 12. Nested SRSWOR sampling implementation hardening (30 October 2026)

The outer repeated-sampling runner now uses the separately testable
`nested_srswor_sample_indices` primitive in
`src/dark_siren_robustness/finite_parent_sampling.py`. Given one random
permutation of the fixed N-record frame, the requested validation samples are
its prefixes. Each prefix is an exact SRSWOR sample; the construction also
makes the smaller sample a subset of every larger sample from the same outer
draw. This supports paired comparisons across validation sizes without
pretending the nested sample sizes are independent.

The primitive validates the RNG type, positive integer parent size, nonempty
and unique positive integer sample sizes, and the upper bound imposed by N.
Tests check exact seeded replay, uniqueness, index bounds, nesting, and
rejection of malformed design declarations. This is an implementation and
sampling-design integrity check, not a bootstrap calibration result.
