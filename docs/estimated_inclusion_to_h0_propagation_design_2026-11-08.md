# Design gate: propagate finite-validation inclusion uncertainty into toy H0 inference

**Date:** 2026-11-08  
**Status:** design only; not implemented or validated  
**Branch:** `research/independent-posterior-audit-claim-fix`

## 1. Objective

Connect the audited probability-stage estimator to the existing low-redshift, Euclidean, selection-conditioned toy H0 likelihood without confusing catalogue inclusion with GW detection selection. The target comparison is the effect of (i) known inclusion probabilities, (ii) estimated plug-in probabilities, and (iii) uncertainty-integrated estimated probabilities on host-density reconstruction and posterior calibration.

This remains a synthetic-methodology experiment. It is not an LVK/GWTC analysis or an observational H0 measurement.

## 2. Data-generating structure

Let (z) denote galaxy redshift, (f(z)) the parent-frame redshift density, and (pi(z;\theta)) the galaxy-catalogue inclusion probability. Catalogue membership is generated by
[
R_i\mid z_i,\theta \sim \mathrm{Bernoulli}(\pi(z_i;\theta)).
]
A validation sample (V) is selected by SRS without replacement from the full parent frame, independently of (R_i), and validation units are excluded from the analysis catalogue (C). The GW detection process is a separate mechanism and must not be folded into (\pi).

The fitted inclusion model is trained only on ((z_i,R_i)_{i\in V}). Parent truth probabilities are available only to the simulator and independent auditor.

## 3. Host-density reconstruction

For a coefficient vector (\theta), define the normalized IPW KDE from retained analysis-catalogue redshifts (z_i\in C):
[
\widehat f_{\mathrm{IPW}}(z\mid\theta)=
\frac{\sum_{i\in C} K_h(z-z_i)/\pi(z_i;\theta)}
{\int_{z_{\min}}^{z_{\max}}\sum_{i\in C} K_h(u-z_i)/\pi(z_i;\theta)\,du}.
]
Apply the declared merger-rate weight (m(z)>0) and normalize:
[
g_\theta(z)=
\frac{\widehat f_{\mathrm{IPW}}(z\mid\theta)m(z)}
{\int \widehat f_{\mathrm{IPW}}(u\mid\theta)m(u)\,du}.
]

The first comparison must use a fixed, predeclared KDE bandwidth across all coefficient draws, but the existing benchmark value 0.8 is not yet an acceptable default. In the current implementation, `bandwidth_factor` is passed directly as SciPy's scalar `gaussian_kde` covariance factor; it is not a multiplier of Scott's rule. A local forensic diagnostic found that this distinction materially changes host-density recovery and H0 posteriors. Resolve the bandwidth semantics and run a parent-density recovery/coverage sensitivity study before selecting the fixed bandwidth. Once selected independently of H0 outcomes, hold it fixed across all coefficient draws and arms; treat bandwidth sensitivity as a separate factorial experiment.

Do not add a second missing-host mixture correction to this already IPW-reconstructed host density. Such a term would require a separately derived likelihood and a clear definition of what population remains absent after reconstruction.

## 4. Selection-conditioned event likelihood

For the existing Gaussian-distance toy model,
[
p(d_k\mid z,H_0)=
\mathcal N\!\left(d_k;\frac{cz}{H_0},\sigma^2\right),
]
and a declared GW detection probability (P(D\mid z,H_0)), define
[
\beta(H_0,\theta)=
\int P(D\mid z,H_0)g_\theta(z)\,dz.
]
For a fixed number (N_{\rm det}) of detected events, the conditional log likelihood is
[
\ell(H_0,\theta)=
\sum_{k=1}^{N_{\rm det}}
\log\!\left[\int p(d_k\mid z,H_0)g_\theta(z)\,dz\right]
-N_{\rm det}\log\beta(H_0,\theta).
]

The same (g_\theta) must enter both event numerators and the GW-detection normalization. Catalogue inclusion (\pi) is not the GW detection probability.

## 5. A defensible first uncertainty-propagation target: modular integration

A clear first target is a modular (cut) posterior in which the validation data determine the inclusion-model uncertainty and the GW data do not feed back into the inclusion coefficients:
[
p_{\rm cut}(\theta\mid V)
\propto
\left\{\prod_{i\in V}
\pi(z_i;\theta)^{R_i}
[1-\pi(z_i;\theta)]^{1-R_i}\right\}p(\theta).
]
Then integrate the **likelihood**, not separately normalized posteriors:
[
L_{\rm mod}(H_0)=
\int \exp\{\ell(H_0,\theta)\}
p_{\rm cut}(\theta\mid V)\,d\theta,
]
and normalize once:
[
p(H_0\mid d,V,C)\propto p(H_0)L_{\rm mod}(H_0).
]

For posterior draws (\theta^{(b)}\sim p_{\rm cut}(\theta\mid V)), approximate the integral using
[
\log L_{\rm mod}(H_0)
\approx
\operatorname{logsumexp}_{b=1}^{B}
\{\ell(H_0,\theta^{(b)})\}-\log B.
]
This is a Bayesian marginalization under the stated modular model. It is **not** the same as averaging bootstrap likelihoods or averaging separately normalized posterior curves.

This is a cut model, not automatically a full joint Bayesian model for the parent galaxy population, catalogue selection, and GW data. A full joint model would additionally require an explicit model for (f(z)), the catalogue-generation process, and the sampling design. The paper must state which inferential target it uses.

## 6. Coefficient uncertainty is not yet available as posterior draws

The current fitter stores an inverse observed-information matrix. That is a model-based asymptotic covariance estimate. It is not a posterior distribution, and drawing Gaussian coefficient samples from it must not be described as Bayesian propagation without a separately justified Laplace approximation.

Recommended implementation sequence:

1. Implement a proper Bayesian logistic validation model with an explicitly declared prior on standardized coefficients.
2. Compare posterior sampling diagnostics and posterior predictive calibration against the MLE and independent raw-record truth.
3. Run prior-scale sensitivity (for example, separate intercept and slope/curvature scales) and document how regularization affects low-retention and near-separation cases.
4. Only then pass posterior coefficient draws into the IPW KDE and H0 likelihood.
5. Keep the MLE plug-in arm as a separate baseline; do not silently replace failures with regularized fits.

The current validation sampling is SRS without replacement from a finite parent frame, while retention labels are generated as independent Bernoulli outcomes conditional on redshift. The intended inferential target must be explicit: a model-based posterior for the Bernoulli inclusion law conditional on sampled redshifts is different from design-based inference conditional on a fixed realized finite population. Do not add a finite-population correction mechanically. Derive it only if the estimand and repeated-sampling framework require it.

## 7. Minimum paired experiment arms

For every shared parent frame, retention realization, validation split, and GW-event realization, compare:

1. **Oracle reference:** parent-frame truth density, used only as a benchmark.
2. **Catalogue-only:** KDE from the observed retained catalogue without inclusion correction.
3. **Known-inclusion IPW:** true (\pi(z)) supplied only to the benchmark arm.
4. **Estimated plug-in IPW:** fitted MLE (\widehat\theta).
5. **Estimated uncertainty-integrated IPW:** integrate the selection-conditioned likelihood over (p_{\rm cut}(\theta\mid V)).

Do not compare unpaired seeds or change the GW selection mechanism between arms. Keep catalogue inclusion and GW detection independently generated and independently audited.

## 8. Required outputs and diagnostics

For each replicate and arm, preserve:
- full scenario key, parent seed, validation IDs, analysis-catalogue IDs, and GW-event seed;
- fit status and optimizer diagnostics;
- coefficient posterior diagnostics (effective sample size, convergence, posterior predictive checks);
- inclusion-probability quantiles and frequency near numerical/positivity thresholds;
- IPW quantiles, Kish and entropy ESS fractions, maximum normalized weight, and top-1%/5% weight mass;
- host-density normalization, support-gap and grid/bandwidth sensitivity diagnostics;
- event likelihood and GW selection normalization (\beta(H_0,\theta));
- posterior mean, median, 68%/95% intervals, boundary flags, and per-replicate coverage;
- raw posterior arrays or a lossless, checksum-verified representation.

A failure in any required arm must remain in the attempt ledger. Report SUCCESS, NON_EVALUABLE, FAILED, and NOT_RUN rather than dropping difficult scenarios.

## 9. Validation gates before scientific claims

**Gate A — inclusion posterior:** validate coefficient posterior computation, prior sensitivity, posterior predictive probability calibration, and behavior under deliberate link/model misspecification.

**Gate B — host density:** independently reconstruct IPW KDEs from raw catalogue records and coefficient draws; test normalization, support, bandwidth, and extreme-weight behavior.

**Gate C — likelihood:** independently reconstruct event numerators and (\beta(H_0,\theta)) from raw events and host-density draws. Verify the same host density enters both terms.

**Gate D — calibration:** run simulation-based calibration under a matched model and repeated-sampling coverage across validation sizes, curvature, retention fractions, and model misspecification. Treat prior-boundary truths separately.

**Gate E — predictive diagnostics:** assess whether pre-posterior metrics predict later coverage failure on held-out simulation scenarios. Fit and evaluate any prediction rule on separate simulation seeds; do not use the same replicates for discovery and claimed predictive validation.

## 10. Claim boundary

Passing Gates A–D would support a controlled synthetic study of finite-validation uncertainty propagation. It would not establish real-survey validity or universal estimator superiority. Gate E is required before claiming that pre-posterior diagnostics predict posterior calibration failure.

**Current status:** design only. No uncertainty-integrated estimated-inclusion H0 posterior has been implemented or validated.
